> A browser-based research prototype for exploring how terrain representation can influence lunar south-polar illumination and geometric Earth-visibility assessments.

## Overview

Lunar south-polar exploration is affected by rugged topography and low solar elevation angles. Small changes in local horizon geometry can alter whether the solar disc or Earth is visible from a particular observer location. SHADOWLINE 4.0 explores this problem through comparative terrain analysis, horizon modelling and interpretable decision classifications.

The project is informed by two complementary NASA terrain products:

- **NASA GSFC PGDA Product 78 — LOLA South Pole Elevation Model:** https://pgda.gsfc.nasa.gov/products/78
- **NASA GSFC PGDA Product 104 — LROC NAC Shape-from-Shading Elevation Model:** https://pgda.gsfc.nasa.gov/products/104

Product 104 is geodetically tied to an a priori LOLA terrain model. The products are therefore treated as complementary terrain representations, not as wholly independent measurements.

### Important implementation and provenance note

**The current public prototype uses a deterministic synthetic paired-terrain benchmark. It does not directly ingest or process the original NASA Product 78 or Product 104 GeoTIFF rasters.** The NASA products are scientific reference datasets for the project's intended methodology. Scenario values generated by the checked-in pipeline are synthetic computational demonstrations and must not be interpreted as empirical findings from NASA raster analysis.

Likewise, the checked-in scenario generator uses mathematical trajectories. The current application does not make live JPL Horizons requests or integrate NAIF SPICE kernels. These services are cited as relevant reference resources, not as currently integrated runtime dependencies.

## What the prototype does

### 1. Terrain and horizon analysis

The Python pipeline constructs parameterised synthetic terrain surfaces and derives observer-centred horizon profiles. The current benchmark uses:

- 720 azimuth samples over 360 degrees (0.5-degree angular spacing).
- Radial terrain sampling and spherical geometric calculations.
- Local coordinate transformations for observer-relative analysis.
- A comparative terrain-difference representation.

The benchmark is designed to demonstrate the analysis workflow. It is not a substitute for processing the original lunar elevation rasters.

### 2. Solar illumination

The application estimates the visible fraction of an extended solar disc relative to the modelled local terrain horizon. It also calculates normalised geometric illumination potential under specified panel-orientation assumptions.

These outputs are geometric model quantities, not measured electrical power or a validated spacecraft power-system simulation.

### 3. Geometric Earth visibility

The application compares the apparent Earth direction with the local terrain horizon to estimate geometric line-of-sight visibility. It does not calculate a complete radio-frequency communications link budget and does not model antenna pointing, transmission hardware or signal performance.

### 4. Decision-sensitivity analysis

The decision engine uses three output states:

- **PASS:** The evaluated condition satisfies the configured geometric criteria.
- **FAIL:** The evaluated condition does not satisfy those criteria.
- **UNKNOWN:** The available model evidence is insufficient for a definitive classification.

The application compares results from its paired synthetic terrain representations and highlights cases where their classifications disagree. A disagreement is presented as a sensitivity requiring investigation, not proof that either terrain representation is correct or incorrect.

## Application workspaces

1. **Compare Navigator** — Select predefined observer locations and scenario windows; inspect horizon and illumination comparisons.
2. **Explain Reversal** — Examine terrain differences and the geometry associated with differing model classifications.
3. **Validate and Provenance** — Review the model assumptions, reference resources and limitations.

The interface includes dual horizon panoramas, a scenario timeline, a 64 × 64 terrain-difference inspector and explanatory provenance panels. The current visual layer uses **HTML Canvas 2D and CSS**; it is not a Three.js or WebGL application.

## Tests

The repository includes four pytest test functions covering analytical behaviour of the synthetic benchmark, including spherical-horizon geometry, synthetic ridge obstruction, azimuthal sampling and bundle structure.

From the `shadowline-v4/` project directory, install the declared Python requirements and run:

```bash
python -m pytest scripts/test_scientific_pipeline.py -v
```

These tests exercise the included synthetic pipeline. They do not validate direct NASA raster ingestion, live Horizons ephemerides or mission-grade performance.

## Scientific scope and limitations

SHADOWLINE 4.0 is an exploratory research and visualisation prototype. It does not certify landing-site safety or replace mission-specific engineering analysis.

The principal next steps are:

1. Ingest and process the original NASA LOLA and LROC terrain rasters with documented coordinate and nodata handling.
2. Introduce independently validated ephemeris inputs, with reproducible frame and time-system conventions.
3. Quantify terrain and illumination uncertainty across model ensembles.
4. Validate computed horizons and visibility windows against independent lunar observations.
5. Extend geometric Earth visibility into a properly specified communications analysis if required.
